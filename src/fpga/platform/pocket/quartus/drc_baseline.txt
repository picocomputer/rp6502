# What the Design Assistant finds today, and why each entry is still
# here. Anything above these numbers fails the build; see
# src/gen/drc_gate.py. Lower a line when a fix lands.
#
# R101  Combinational logic used as a reset, unsynchronised.
#       mrst_n is the real one: the core's master reset, 7916 fanout on a
#       global network, released asynchronously. Blocks leave reset in
#       whatever order the routing gives, which is a different order
#       every fit. Fixed: asserted asynchronously and released
#       synchronously now, once per clock domain, in pocket_core.sv.
#       What is left is aud_opl's core_ic_n, the vendor core's own.
R101 1
#
# D101  Data crossing clock domains without a synchroniser. Almost all of
#       this is the clk_sys/clk_rv seam, which rp6502.sdc declares one
#       synchronous group on purpose — the tool cannot see the SDC and
#       counts it as asynchronous. Real, but not what this rule thinks.
D101 551
#
# D103  Data bits not correctly synchronised. pocket_file's r_op, the
#       file command opcode. Traced and judged safe: r_op is written
#       once per command and cannot change again until busy clears, and
#       the host does not read it until go_t2 != go_t3, three clk_74a
#       flops after the toggle that announced it. Data held still behind
#       a synchronised toggle is the correct handshake; the tool flags
#       it because it can see the three bits crossing and not the
#       handshake, the same blind spot that flags every gray pointer
#       under D102. Left as found.
D103 3
#
# D102  Multi-bit crossings that are synchronised but may land
#       misaligned. Most are pocket_fifo's gray pointers, where one bit
#       changes per step and misalignment is safe by construction — the
#       tool cannot know the encoding. The bridge's held parameter buses
#       and Analogue's own controller buses make up the rest, along with
#       r_op again.
D102 22
#
# C104  A clock source driving something other than a clock port:
#       clk_74a, which Analogue's own framework also uses as data.
C104 1
#
# R102  An external reset not double-registered: bridge_spiss, from the
#       platform.
R102 1
#
# C106  One clock driving both edges, and it stays. rp6502.sv takes the
#       soft CPU's two narrowings on negedge clk_sys.
#
#       This was first written down as a hack to be backed out, and that
#       was wrong. The signal being narrowed is rv_soc_bus_stb, which is
#       rv_soc_bus_pend AND bus_rdy — one term a clk_rv flop, the other
#       from clk_sys logic decoding a clk_rv address. It settles partway
#       through the clk_sys period by construction, so a rising-edge
#       sample asks while it is still moving, and what a wrong answer
#       costs is not a wrong value but a bus access that never happens.
#
#       Narrowing bus_pend instead does not help: the edge that matters
#       is the one where the machine becomes ready, so detecting
#       bus_pend and merely gating the pulse with bus_rdy would consume
#       the edge on a cycle the machine could not serve and lose the
#       access for good. And bus_rdy cannot be made single-rate — it
#       decodes a clk_rv address against a clk_sys busy.
#
#       A signal that settles mid-period wants sampling late in the
#       period. That is the falling edge. The duty-cycle dependency it
#       brings is real and is the price; 9.9 ns nominal against a race
#       that had none.
C106 1
