# drc_gate.py in src/host/pocket/gen fails the build when its count of
# findings for a rule in the Design Assistant report is above the number
# given here. The fitter can copy a register, and the report names the
# copy with a ~DUPLICATE suffix. The gate counts the copy and the
# register as one node, so two findings that differ only in which of the
# two they name are counted once, and a number here can be lower than
# the structure count in the report.
#
# R101  opl.sv's Equal2~1 is the chip_rst == 0 comparator, which drives
#       the write-side reset of the vendored OPL's afifo. chip_rst is a
#       counter on clk_mach, which also clocks that write side.
#       wiring.sv's resb_eff is the AND of resb and the inverse of the
#       savestate engine's hold_res, and it drives the asynchronous
#       resets of the 6502 and the 6522, which run on clk_mach. resb is a
#       flop on clk_mach, and hold_res is a flop on clk_sys. clk_mach is
#       clk_sys through a clock gate, so each reset changes just after a
#       rising edge of clk_sys, and its release is timed against the
#       registers it resets as recovery and removal.
R101 2
#
# D101  Every finding is a crossing between clk_74a and clk_sys, in one
#       direction or the other:
#
#         320  io_pad_controller  cont1 to cont4 key, joy and trig
#         160  pocket_bridge      utz_74, utzm_74, utzs_74, kb_74,
#                                 slot_size
#         152  pocket_file        the command parameters, which are
#                                 pocket_file_id, _slotoffset,
#                                 _bridgeaddr and _length; r_op;
#                                 result_q, err_q, tmo_q and wrote_q
#          32  core_bridge_cmd    rtc_epoch_seconds
#          32  sst_engine         hold
#          20  pocket_sst         ask, ask_t, start_hold
#           1  core_top           mach_clk_en
#
#       cont1 to cont4, utz_74, utzm_74, utzs_74, kb_74 and
#       rtc_epoch_seconds are levels. Each lands on a two-flop
#       synchronizer in pocket_bridge and is taken only when two
#       consecutive samples agree. slot_size, the command parameters,
#       r_op, result_q, err_q, tmo_q, wrote_q and ask cross beside a
#       toggle, and each is read in the receiving clock domain only after
#       that toggle has passed through its synchronizer: settle_t, go_t,
#       ret_t or ask_t. When sst_engine is not in reset, it changes hold
#       only while its rvalid is low, and pocket_sst copies hold into its
#       register of the same name only once rvalid_s2, its synchronized
#       copy of rvalid, has been low and then high again since ask was
#       last written. ask_t, start_hold and mach_clk_en are single bits
#       that land on the first flop of a synchronizer: idx_t1, save_s1
#       and running_s1.
D101 717
#
# D102  Each finding is a multi-bit crossing that is synchronized but
#       may land misaligned:
#
#         17  the level buses from D101, on their pocket_bridge flops
#          8  the Gray-coded pointers of the pocket_fifo queues in
#             pocket_bridge, pocket_dbg, pocket_dbglog and pocket_i2s,
#             which the report lists as seven or eight depending on
#             which of them the fitter copies
#          1  pocket_bridge's upd_g_74, a Gray-coded count of slot
#             updates
#          1  pocket_file's r_op
#          1  rx_byte in Analogue's io_bridge_peripheral
#
#       A Gray-coded pointer or count changes one bit per step, so a
#       sample taken during a change reads the old value or the new one.
#       D101 gives the argument for the level buses and for r_op.
D102 28
#
# D103  The three findings are the bits of r_op, pocket_file's command
#       opcode, which is decoded on clk_74a into the read, write,
#       openfile, getfile and flush strobes. r_op is written on the
#       clk_sys edge that toggles go_t, and the clk_74a side decodes it
#       only once go_t2 differs from go_t3.
D103 3
#
# C104  clk_74a drives the PLL's reference input, which the report lists
#       as a non-clock port. The PLL also makes clk_ph, a clk_sys-rate
#       output shifted so that it is low across the first edge of clk_a2
#       after clk_sys's and high across the second, and xram.sv samples
#       it as data into ph on clk_a2 to tell the two edges apart. The
#       phase is the PLL's, and the path from the clk_ph net into ph is
#       timed as any other data path.
C104 2
#
# S104  ph in xram.sv, from the same clk_ph sampling: its clock, clk_a2,
#       and its data, clk_ph, are two outputs of one PLL.
S104 1
#
# R102  bridge_spiss, the bridge's SPI select pin, is used directly as
#       the asynchronous reset of rx_byte_done and rx_latch_idx, two of
#       the bridge_spiclk registers in Analogue's io_bridge_peripheral.
R102 1
#
# C106  clk_sys clocks soc_stb_n in wiring.sv on its falling edge.
#       soc_stb_raw, the soft CPU's bus strobe, is the AND of
#       soc_bus_pend and bus_rdy, which are driven by registers on
#       clk_rv, clk_sys and clk_mach. clk_rv and clk_mach rise only on
#       rising edges of clk_sys, so soc_stb_raw changes just after a
#       rising edge of clk_sys. It is therefore sampled half a clk_sys
#       period later, 9.9 ns nominal, and the path into soc_stb_n depends
#       on the duty cycle of clk_sys.
C106 1
